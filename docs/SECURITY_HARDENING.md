# اصلاحات امنیتی پنل فصلی — 2026-11-04

دامنه فقط پروژهٔ دوم است. ورود اصلی مشترک و امکان تغییر نقش مطابق درخواست کاربر حفظ شده‌اند. این ورود همچنان اختیارات تمام نقش‌ها را دارد؛ حساب‌های مستقل به هویت خود محدود می‌مانند.

## دسترسی فایل‌های محلی

وراثت پوشهٔ اصلی پروژه از والد متوقف و مجوزهای عمومی Users و Authenticated Users حذف شد. مجوز مالک، SYSTEM، Administrators و هویت‌های توسعه حفظ شد؛ فایل‌های حساس با والد محدود همگام شدند. ACL فایل‌های .env، ورود اصلی، ورود Codex، دیتابیس، پشتیبان و کد بررسی شد. پوشهٔ پروژهٔ اول تغییر نکرد.

بعضی فایل‌های نصب قبلی وابستگی‌ها با پروژهٔ اول هاردلینک بودند. نصب فعال جدید با روش copy ساخته شد و نمونهٔ mammoth تنها یک مسیر فیزیکی دارد؛ `pnpm-workspace.yaml` این روش را برای نصب‌های بعدی نگه می‌دارد. ساختار نصب قبلی در مسیر محلی و نادیده‌گرفته‌شدهٔ `.runtime/security-old-node_modules` کنار گذاشته شده و در اجرای برنامه استفاده نمی‌شود. محتوا یا ACL فایل‌های هاردلینک آن مستقیم تغییر داده نشد.

این مجوزها تنظیم محلی ویندوز هستند و توسط Git منتقل نمی‌شوند؛ هنگام استقرار یا کپی روی دستگاه دیگر باید دوباره کنترل شوند. نسخه‌های پشتیبان مطابق تصمیم قبلی کاربر داخل پروژه باقی مانده‌اند.

## ورود و تغییر رمز

- حداکثر پنج تلاش ناموفق ورود در پنجرهٔ پنج‌دقیقه‌ای برای هر IP؛ ورود موفق فقط سهم درخواست خودش را آزاد می‌کند. موفقیت یک حساب، خطاهای حساب دیگر را صفر نمی‌کند.
- حداکثر پنج تلاش ناموفق تغییر رمز در پنج دقیقه برای هر فرد، مستقل از تعداد نشست‌های آن فرد. خطا با نام رویداد `password.change.failure` ثبت و در گزارش امنیت نمایش داده می‌شود؛ رمز، متن درخواست یا توکن در رویداد ذخیره نمی‌شود.
- درخواست پیش از محاسبهٔ رمز سهم خود را رزرو می‌کند؛ چهار عملیات ورود/تغییر رمز به‌صورت هم‌زمان مجاز است. ظرفیت حافظه محدود است و با پرشدن آن قفل‌های زنده حذف نمی‌شوند. پاسخ محدودیت دارای Retry-After است، به‌جز محدودیت قدیمی هم‌زمانی ورود که پیام تلاش مجدد دارد.
- شمارنده‌ها حافظه‌ای‌اند و با بازراه‌اندازی سرور صفر می‌شوند؛ برای اجرای چند نمونه پشت پراکسی باید شمارندهٔ مشترک و سیاست شناسایی IP طراحی شود. استقرار فعلی تک‌نمونه و loopback است.

## وابستگی و مرورگر

argparse در بازهٔ مجاز همان وابستگی از 1.0.3 به 1.0.10 ارتقا یافت. lodash 3.2.0 حذف شد؛ بقیهٔ نسخه‌ها ثابت‌اند. `pnpm audit --prod --json` در زمان آزمون صفر آسیب‌پذیری شناخته‌شده نشان داد. استخراج متن فارسی DOCX و ورودی CLI نیز آزموده شدند.

CSP بارگذاری اسکریپت را به همان مبدأ محدود می‌کند؛ اسکریپت درون‌صفحه و handler متنی مجاز نیست. object غیرفعال و frame-ancestors برابر none است. X-Frame-Options: DENY، Referrer-Policy: no-referrer و nosniff اعمال می‌شوند. inline style برای چیدمان و نمودارهای پویا حفظ شده است. خواندن اکسل در Worker، ورود و گردش رابط با این سیاست آزمایش شد.

## شواهد و حدود آزمون

57 آزمون خودکار، کنترل نحو 153 فایل و 70 کنترل مرورگر روی دیتابیس ساختگی موفق‌اند. خطای اجرای مرورگر، درخواست ناموفق و نقض غیرمنتظرهٔ CSP مشاهده نشد؛ آزمون تعمدی درج اسکریپت مسدود شد. هیچ درخواست زنده‌ای به مدل برای این تغییرات ارسال نشد.

پس از پشتیبان کامل و بررسی نبود کار فعال، فقط فرزند پنل جدید بازراه‌اندازی شد. هش تمام رکوردها و فایل‌های خام هر دو پروژه قبل و بعد یکسان است؛ Git و پردازش پنل قبلی ثابت‌اند. گزارش‌های محلی در `outputs/security-fixes` نگهداری می‌شوند. این بررسی معادل آزمون نفوذ شبکه یا تضمین نبود تمام آسیب‌پذیری‌ها نیست.
